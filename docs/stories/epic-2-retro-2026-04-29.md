## What Changed

- `/bmad-next` now specifies a one-step transaction lifecycle: select, open a run record, load step context, run sequential tasks, validate outputs and mutation scope, repair within limits, confirm evidence, then update state.
- Task contracts now include persona, explicit inputs, downstream output passing, allowed paths, required outputs, self-check, validation, and repair policy.
- Schemas and templates now support validation policy, run/task records, repair history, failure reports, mutation scope, and review/fix history.
- Command reference, examples, README, and `/bmad-loop` now document optional steps included by default, task validation failure, repair success, and repair exhaustion.
