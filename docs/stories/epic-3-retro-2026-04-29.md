# Epic 3 Retrospective: Run Controlled BMAD Loops

## Status

done

## What Changed

- `/bmad-loop` now defines explicit target parsing for `next-story`, story, story range, epic, phase, and step targets, including malformed target diagnostics before mutation.
- Dry-run loop planning now reports the resolved target, likely step sequence, expected outputs, evidence, mutation scope, optional-step policy, limits, and stop conditions without executing steps.
- Real loop execution is specified as repeated `/bmad-next` transactions, with target evaluation between iterations, max-step stopping, optional-step skip reporting, loop records, and loop summaries.
- Stop reports now enumerate target reached, max steps, checkpoints, reconcile needs, missing inputs, ambiguous completion, validation failures, repair limits, unresolved targets, out-of-scope mutations, and missing BMAD prerequisites.

## Review Findings

- Self-review found the Epic 3 surface consistent with project rules: prompt-first, script-light, BMAD as prerequisite, workflow step as atomic transaction, artifacts/frontmatter as proof, and state as an index.
- No blocking follow-ups remained after aligning `/bmad-loop`, command reference, examples, README, schemas, templates, story records, and sprint status.
- Residual risk: loop behavior is still specified rather than executable. JSON syntax validation can check schemas, but target resolution, artifact comparison, and stop report quality depend on future agent adherence or a later runtime.
